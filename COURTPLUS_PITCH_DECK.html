Executive Product Status & Pitch Document — August 2026

1 Executive Summary & Truth Verdict

Court+ is a production-grade Flutter application that delivers a complete, polished booking experience from sign-up through slot selection and a 4-step booking wizard. The authentication system is fully functional — email/password registration, OTP verification, session persistence, and guest mode all work end-to-end against a live Supabase instance. The slot-locking engine, powered by real PostgreSQL RPCs, successfully acquires and releases 15-minute holds on court slots, demonstrating the core transactional logic that differentiates this app from a simple directory listing.

The honest verdict: Court+ is a high-fidelity UI prototype with a real backend skeleton. It is not yet shippable to production. The app needs a connected payment gateway (Stripe), configured OAuth providers (Google/Apple), populated social tables (moments, likes, comments, favorites, follows), real court media assets, and a messaging/chat service to graduate from a compelling demo to a market-ready product. The architecture is clean, the codebase compiles with zero errors, and the foundation is solid — but the last mile of integration work remains.

3 Partially Implemented Features PARTIAL

Booking Pipeline (Steps 1–4)

All 4 steps are wired. Step 1 selects slots with real RPC locking. Steps 2–3 collect details. Step 4 inserts a booking record with status pending and navigates to a "payment" step — but no real payment processing occurs. The payment method is a hardcoded string.

Social RPC Integration

RPC calls for add_moment_comment, like_moment/unlike_moment, follow_user/unfollow_user, and add_favorite/remove_favorite are all wired in the UI. The RPC functions exist in the database. However, the underlying tables contain zero real rows — all interactions are ephemeral.

Localisation (EN/AR)

AppStrings contains 220+ keys for bilingual support. The framework is wired into most screens. However, several screens still contain hardcoded English text, and the booking wizard screens are not fully localised.

Moments Feed

The moments grid renders with masonry layout, like/comment/share buttons, and a fallback of 3 hardcoded mock posts when the backend returns empty. The backend moments table has a schema but no data.

4 Missing, Broken, or Unwired Components BROKEN

✗ Payments

Stripe publishable key is missing from .env. The confirm_booking_payment RPC is never called — the booking wizard stops at a mock "payment method" string. No real charging occurs.

✗ Google / Apple OAuth

Buttons render on login and signup screens. Tapping throws "Unsupported provider: provider is not enabled" — requires client ID/secret in the Supabase dashboard.

✗ Match Creation

start_match_screen.dart has a full UI form (level, date/time, location, player profiles) but the "Create Match" button performs no database operation. No match records are ever created.

✗ Messaging / Chat

Chat icons (Ph.chats_circle) appear in the home header, explore header, and bottom nav. None are wired to any screen — tapping does nothing. No messaging backend exists.

✗ Phone Auth

The signup form collects phone number with country code picker. The backend SupabaseService has no signInWithPhone or signUpWithPhone method wired.

✗ Explore Map

The explore screen renders a static map area. No Google Maps, Mapbox, or OSM SDK is integrated. The map is purely decorative.

✗ Placeholder Assets

All court images (court1.jpg, court2.jpg) are the same placeholder. The app logo is a generic GSAP placeholder icon. No real venue photography is used.

✗ No Tests

Zero automated test coverage. No widget tests, no integration tests, no unit tests for providers or services.

6 Next Steps to Production Readiness

1 Payment Gateway

Add Stripe publishable key to .env. Wire the payment step to call confirm_booking_payment RPC. Enable Stripe Webhook endpoint in Supabase Edge Functions.

2 OAuth Configuration

Register Google and Apple OAuth apps. Add client ID/secret to Supabase Authentication → Providers. Verify Google & Apple sign-in flows end-to-end.

3 Social Table Population

Seed the moments, moment_likes, moment_comments, favorites, and followers tables with realistic data. Wire match creation to the matches table. Remove mock fallbacks.

4 Messaging Service

Implement a chat backend (Supabase Realtime or a dedicated service). Wire the chat icons to an InboxScreen and ChatScreen. Add push notifications.

5 Real Media & Map

Replace all placeholder court images with real venue photography. Integrate Google Maps or Mapbox SDK for the explore screen map. Add proper map markers with court locations.

6 Testing & Hardening

Add widget tests for critical flows (auth, booking, profile). Add integration tests for the booking pipeline. Set up CI with dart analyze and test runner. Audit and fix remaining 16 info-level lints.
